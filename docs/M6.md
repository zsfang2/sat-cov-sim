# 候选点选择与隔离评价

接口位于 `satellite_coverage.engine.candidate_selection`。候选点是安装位置；与 M5 中的候选卫星链路是不同维度。首期采用等成本、固定 AGL 高度的有限候选集，最多 256 个位置。

```python
development = DevelopmentScores.from_mapping(development_mapping)
receipt = select_candidate(development)
# 先保存 receipt，再加载独立的共同留出参考。
holdout = HoldoutScores.from_mapping(holdout_mapping)
evaluation = evaluate_selection(receipt, holdout)
```

CandidateSet 保存 ID、本地 east/north 米坐标、坐标依据、统一 AGL、高于零的相同安装成本、可行性及原因。全部候选保留；不可行点不进入选择或 oracle。PassRegistry 保存完整观察区间、UTC 起止、来源依据及 development/holdout 标签；区间不得重叠，留出在开发之后。数据对象以经过验证的不可变 canonical JSON 保存，to_mapping 返回副本。

DevelopmentScores/HoldoutScores 均包含同一候选集及过境注册表、模型/信息角色/来源声明，以及该划分内完整的候选点×过境表。每行必须分别提供 sufficient_s、insufficient_s、invisible_s、unknown_s、longest_unavailable_s 和 source_id。四类累计秒数之和必须等于整个观察区间（容差 1e-6 秒），不能通过删除未知或无星时间改善分母。时间与费用不做无依据加权。

固定选择目标为全开发区间的 `insufficient + invisible + unknown` 秒数，即保守的条件传播机会不足上界。未知时间计为上界惩罚，原始分量仍独立输出；这不是实测断链时长，也不是业务达标条件。穷举所有可行点；距最小值不超过 1e-6 秒的候选为并列集合，选择字典序最小 ID。ranking 按原数值排序，tie_ids 明确记录近似并列，避免把并列规则藏进舍入。

选择器只接受 DevelopmentScores，不接收留出表。SelectionReceipt 内含完整开发证据和派生决策；加载时重新按固定规则计算，篡改所选 ID 或开发统计会被拒绝。评价器单独接受凭据与 HoldoutScores，并核对候选集、过境注册表身份。不能把已注册的留出行重新标记为开发行，也不能更换候选或参考来比较方法。

这提供确定性 API 数据隔离及可复查证据，不是面对恶意 Python 调用者的加密安全边界；调用者仍须如实提供过境来源和观测依据。实际工作流应在读取留出参考前保存选择凭据。真实业务标签是否可信由上游数据来源负责。

评价时才计算留出 oracle。部署 regret 使用同一保守目标的“所选点−留出最优点”；负数超过 1e-6 秒拒绝，舍入范围内归零。相对基线 gain 可正、可零、可负。全部原始分量、候选排名、安装成本和最长已知不足独立保留；最长值取单个已观测过境的最大已知不足段，不跨未观测间隔连接。无可行点时 selected/oracle/regret 为 null，观察分母及所有候选统计仍保留。

`score_row_from_events(events, site_id, pass_id, registry)` 将一个安装点的多星机会转换为评分行，校验事件观察时间与注册区间一致。任何一颗足够则记 sufficient，未知机会单列；已知无机会时，有已知不足链路记 insufficient，全不可见或无星记 invisible。无星全时段不会消失。不同信息层级可以用显式声明的代理量形成表，但不得把天空轮廓代理标成已验证接收功率。

`compare_evaluations` 强制各方法使用同一留出表身份并输出 gain/regret，包括无收益。计算成本由实验单独计时记录，不混入固定安装成本或目标。minimum_useful_gain 与 service_eligibility 保持未定/未知。
