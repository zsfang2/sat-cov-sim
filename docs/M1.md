# M1：统一几何与分量链路接口

本模块实现 `plan.md` 的 M1 首期标量能力。固定 ECEF、人工方向序列、TLE 轨道通过同一个 `engine.links.calculate_links()` 入口计算。它不进行服务卫星选择，也不实现地形遮挡、方向缓存或参考数据集生成。

## 入口及配置

```python
from satellite_coverage.config.link import LinkConfig
from satellite_coverage.engine.links import calculate_links

config = LinkConfig.from_mapping(mapping)  # 不可变、严格字段检查、配置哈希
result = calculate_links(config, catalog=None)  # TLE 模式传 parse_catalog(raw) 的结果
```

统一顶层字段：`schema_version=1`、`experiment_id`、`start/end/step_s`、`receiver`、`source`、`budget`。不接受未定义字段。时间必须有时区，输出 UTC；步长至少 1 ms、以整数微秒表达、最多 10,001 点和 7 天。包含两个端点，末步允许短于步长。

| 来源 | source 字段 | 语义 |
| --- | --- | --- |
| 固定位置 | `mode: fixed_ecef`、`candidate_id`、`position_ecef_m: [x,y,z]` | 固定在地固 ECEF 中，不是在惯性系中固定 |
| 人工方向 | `mode: direction_sequence`、`candidate_id`、`directions` | 每个采样点对应一组 `azimuth_deg/elevation_deg/slant_range_m`；方位北起顺时针，度/米 |
| 人工 ENU | `mode: relative_enu_sequence`、`candidate_id`、`positions_enu_m` | 人工方向的向量表示；相对天线，不重复添加 AGL |
| 轨道 | `mode: tle`、`candidate_id`、`norad_id`、`tle_policy`、`max_age_days` | SGP4/Skyfield 转 ITRS 后进入相同几何流程，保留元素哈希和时效 |

天线高度只接受两种显式口径：

- `height_basis: ellipsoid`：给出 `antenna_ellipsoid_height_m`。
- `height_basis: orthometric_plus_geoid`：给出 `ground_orthometric_height_m`、`geoid_undulation_m`、`antenna_agl_m`、`vertical_datum`，按 `h=H+N+AGL` 转换。geoid 必须与给定正高基准匹配，模块不自行推断。

两种口径都必须给 `lon_deg`、`lat_deg` 和 `basis` 来源或假设描述。

## 链路与方向图

`budget` 包含 `frequency_hz`、`power`、`receiver_antenna`、`losses`、`threshold` 和 `assumption_basis`。`power` 接受 EIRP 或“发射功率 + 发射增益”两种互斥形式。

接收方向图支持：

- `isotropic`：`gain_dbi` 和 `basis`，表示方向无关的声明增益，理想全向用 0 dBi。
- `cosine`：`peak_gain_dbi`、`floor_gain_dbi`、`exponent`、非零 `boresight_enu` 和 `basis`。轴固定在接收点 ENU，入射方向按天线指向卫星定义。前半球增益为 `max(floor, peak + 10*exponent*log10(cos(theta)))`；后半球使用 floor。这是声明的解析方向图，不是某款终端的测量模型。

`losses` 必须包含 atmosphere/local/misc 三项：

- 关闭：`{enabled: false, reason: ...}`，产生显式禁用的零损耗。
- 启用：`{enabled: true, value: 1, status: known, reason: ...}`，或 `value: null` 加 unknown/not_computed/failed 等状态。

损耗采用非负 dB，增益在功率或天线字段单独声明。FSPL 是必需基线。首期大气使用显式固定情景；未连接动态气象或完整 ITU-R 模型。每个分量记录效应、求解器、开关、参考功率和标量平均口径。

可选门限为 `{received_power_dbm: ..., basis: ...}`；无门限时填写 null。不输出 SNR，不能把功率裕量直接当作实际通信服务判定。

## 结果与错误

每条样本包含时间、候选身份、配置哈希、输入类型、geometry、budget 和 status。`service_eligibility` 始终为 unknown。

| 情况 | 样本 / 功率状态 |
| --- | --- |
| 正常计算 | 样本 computed；是否有已知功率继续看 `budget.received_power.status` |
| 几何位于地平线及以下 | 几何保留；功率 not_applicable |
| 启用但未知的损耗 | 分量保留 unknown；功率 not_computed，不填零 |
| 没有历史元素 / 超龄 | 每个时间点保留 not_computed 样本与原因 |
| 传播失败 / 零距离 | 样本 failed；不能转成无遮挡或空成功 |
| 分量失败且影响功率 | 保留分量 failed，样本 failed，整次结果 complete=false |

`complete` 表示所有请求样本完成求值，不表示全部功率已知、可见或提供服务。配置非法在传播前拒绝；运行期单点失败保留记录，不补选其他卫星。

## 无界面验收命令

在仓库根目录运行，每次使用新输出目录：

```bash
bash scripts/python_geo.sh -m satellite_coverage.experiments.link \
  --config configs/m1_fixed.yaml --output output/m1-fixed-new
bash scripts/python_geo.sh -m satellite_coverage.experiments.link \
  --config configs/m1_sequence.yaml --output output/m1-sequence-new
bash scripts/python_geo.sh -m satellite_coverage.experiments.link \
  --config configs/m1_tle.yaml \
  --tle ../Satellite-Ground-Radiomap/data/starlink-2025-tle/2025-01-01.tle \
  --output output/m1-tle-new
bash scripts/python_geo.sh scripts/verify_orbit_link.py \
  --run output/m1-tle-new --output output/m1-verification-new.json
```

运行记录保存配置、原始输入、源码 ZIP、环境、结果、验证状态及产物哈希。`passed` 是执行验证，不是物理真值认证。旧 `experiments.orbit_link` 与 `engine.orbit_link.calculate_orbit_links` 仍兼容首批轨道配置，通过适配层调用统一引擎。

阶段证据见 [M1 验收报告](../reports/m1/acceptance.md)。
