# TLE 可见窗口与 DEM 工作台

这是实际读取 TLE 和 GeoTIFF 的本地工作台，已拆分成独立前后端。本仓库保留数值计算、数据读取与 JSON API；页面、静态资源、展示服务和浏览器检查在同级目录 `satellite-coverage-demo`。原离线概念页面已迁入前端的 `concept/index.html`。

## 启动与访问

已有项目 `.venv` 时，在仓库根目录执行：

```bash
bash scripts/python_geo.sh -m satellite_coverage.explorer --port 8766
```

另开终端启动独立前端，只需 Python 标准库：

```bash
cd /home/Users_Work_Space/zsfang/satellite-coverage-demo
python server.py --port 8765 --backend http://127.0.0.1:8766
```

在同一台电脑访问 **http://127.0.0.1:8765**。两个服务均仅监听回环地址，浏览器的 `/api/*` 请求由前端转发到固定后端。服务器上使用时只需转发 **8765**；或在自己的电脑建立 SSH 转发：

```bash
ssh -L 8765:127.0.0.1:8765 zsfang@<服务器地址>
```

保持 SSH 连接，在自己的浏览器打开 **http://localhost:8765**。本地转发端口与前端端口保持一致；后端 8766 无需转发。两个进程必须保持运行，分别用 `Ctrl+C` 关闭。新机器按 [PILOT 环境说明](PILOT.md) 安装后端依赖；前端运行时不需要仿真包。

可指定数据根目录：

```bash
bash scripts/python_geo.sh -m satellite_coverage.explorer \
  --port 8766 --data-root /home/Users_Work_Space/zsfang
```

文件浏览和路径读取限制在这个目录内。默认值是当前源码仓库的上一级；安装到其他位置后应显式指定数据根目录。本应用不修改原始数据文件，最多保留最近 8 个任务于进程内存，关闭后释放。需要保留结果时及时导出 JSON。

## 操作步骤

1. **解析 TLE**：输入服务器文件路径，或者点击“浏览…”在弹窗中选择；也可以“从本机选择文件…”上传本机 TLE 文本。读取支持 `.tle` / `.txt`，最大 32 MiB，接受两行和带名称三行形式，检查行长、编号与校验和。界面显示轨道记录数、不同卫星数、重复记录及历元范围。
2. **设置时间**：起点和终点均为 **UTC**，单次最多 7 天。解析文件后默认采用最早历元所在日 00:00–02:00；可以修改，不会把历史 TLE 默认用于当前日期。
3. **设置终端**：单点输入经纬度，或在 DEM 图上单击。区域输入西/南/东/北边界，使用 2×2、3×3 或 5×5 网格；可直接采用当前地图范围。默认“任一采样点可见”，也可选“全部采样点同时可见”。暂不支持多边形及跨日期变更线区域。
4. **计算窗口**：设置最低仰角、最大 TLE 历元偏差及终端椭球高。卫星编号留空计算全部；展开目录可按名称或 NORAD 筛选并选择。后台显示进度，支持取消。已有一个任务运行时不能同时再开一个。
5. **检查结果**：查看按卫星排列的窗口、UTC 时间轴、时长、起止截断，以及跳过/失败列表。点击“查看轨迹”显示仰角曲线和星下点轨迹；区域模式可以切换曲线对应的采样点。JSON 保存完整参数、来源哈希、源码哈希、软件版本、逐点窗口和异常列表；CSV 保存当前任务全部单星窗口，不受表格筛选或分页限制。
6. **浏览 DEM**：选择服务器 `.tif` / `.tiff` 后读取。图上滚轮缩放、拖动平移；也可定位终端/区域或 DEM 全范围。鼠标位置显示经纬度与显示像元数值，nodata 保持缺失。色带随当前视图调整。原始大 DEM 不上传到浏览器。

## 计算与显示口径

- **轨道与窗口**：使用 [Skyfield 的 SGP4 与升落事件搜索](https://rhodesmill.org/skyfield/earth-satellites.html#finding-when-a-satellite-rises-and-sets)，以 WGS-84 观测点的几何仰角达到门限为可见。事件搜索使用库内 0.5 s 数值容差；这不是轨道实际位置或过境时间的精度承诺。
- **同一卫星多条 TLE**：优先取起点之前最新的一条；若没有，取最早未来历元并明确标记。相同历元以元素行 SHA-256 确定排序。同一任务中不切换元素。完全相同的元素对去重，不同历元不会重复计为不同卫星。
- **历元有效性**：检查所选元素相对整个请求时段两端的最大偏差，默认上限 7 天，可设 0.01–30 天。这是演示筛选政策，不是物理精度保证。过期卫星跳过并使结果标记为不完整；传播错误保留为失败，不能当作没有可见窗口。
- **边界**：请求起点已可见或终点仍可见时，窗口裁剪到请求区间并标记。支持多次过境与连续可见窗口，不要求每组事件恰好是“升起—最高点—落下”。
- **区域**：每个采样点独立搜索事件。同一卫星的区域窗口对逐点窗口取并集（任一）或交集（全部）。星座覆盖则先合并每个点的全部卫星窗口，再按区域口径聚合；因此“全部”可以由不同卫星分别覆盖不同点。规则网格不能证明区域内部每个连续位置的可见性，也没有模拟终端可服务性或卫星容量。
- **轨迹图**：721 个等间隔采样只用于显示，长区间的曲线可能漏画很短的峰。事件窗口独立求解，不从这条曲线推断；详情中的窗口峰值使用升落/最高点事件计算。
- **DEM**：先用 Rasterio 窗口读取将原栅格最近邻抽稀至最多 768×768，再重投影成默认 384×384 的 EPSG:4326 显示栅格，保留 nodata，应用波段 scale/offset。GDAL 缓存上限 32 MiB，避免全国原始栅格直接参与完整重投影。两次最近邻采样可能漏过很窄的地物；显示最小/最大值是重采样视图统计，不是整幅原始 DEM 的统计；坐标图是经纬度视图，不是等距测量地图。
- **高度**：观测点输入是 WGS-84 **椭球高**，不是 AGL。现有中国 DEM 的垂直基准和单位仍未核实，因此显示原始数值并标记单位未知，不自动接入轨道终端高度或地形遮挡。
- **来源**：TLE 计算记录完整文件 SHA-256 和所选元素行 SHA-256。DEM 交互预览只记录路径、大小、mtime；不在每次拖图时重复哈希 8.6 GiB 文件。第一周完整 DEM 哈希证据仍在原验收记录中。

这些功能是可运行的轨道/数据探索入口，不表示完整 M1/M3、地形参考模型或通信服务窗口已经验收。

## 验证与维护

```bash
bash scripts/python_geo.sh -m pytest tests -q
bash scripts/python_geo.sh scripts/verify_explorer.py --all-satellites
```

第二条命令读取本地真实数据，保存 `output/explorer-verification.json`：全星座单点两小时窗口、最多 20 颗可见卫星的 3×3 区域、真实 DEM 预览和轨迹采样。浏览器联调已迁到独立前端：

```bash
cd /home/Users_Work_Space/zsfang/satellite-coverage-demo
python -m unittest discover -s tests -v
python scripts/check_explorer_browser.py \
  --backend-python ../satellite-coverage-sim/.venv/bin/python \
  --data-root /home/Users_Work_Space/zsfang --no-sandbox \
  --screenshot output/explorer-browser.png
```

浏览器检查需要安装 Chrome，启动真实后端子进程并通过前端代理访问；`--no-sandbox` 仅在容器必须时用于本地测试页面。

实测该 TLE 有 14,918 条元素记录、6,490 颗不同卫星、763 条完全重复记录。以上默认点位/两小时时段/10° 仰角，全星座均完成，得到 2,627 个单星窗口，轨道计算约 24 秒（本机实测）；3×3 区域的 20 颗可见卫星得到 30 个区域窗口。这个速度不能直接外推到任意机器、七天时段或 5×5 全星座任务。

前端位于独立目录 `satellite-coverage-demo/web/`，修改后刷新页面；修改后端 Python 模块后重启 API。两侧分别提交版本；保持 API 契约与联调记录同步，第一周历史验收记录无需覆盖。接口约定见 [EXPLORER_API.md](EXPLORER_API.md)。
