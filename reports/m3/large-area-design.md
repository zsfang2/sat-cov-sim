读取器未修改，测量脚本的 SHA-256 随 [机器记录](reader-resource-measurements.json) 保存。
本报告为 G02 编码约束，不是 M3 验收，也不是扩大半径后的稳定性结论。

## 已执行的工作

官方 `ask-codex.sh` 分析成功退出 0，记录在
`.humanize/skill/2026-10-09_08-08-51-2208192-228e951a/output.md`。
采用其两层有界读取建议；不采用未经测量的 memmap 扩展，也不放宽浮点等价条件。
咨询中 `TerrainGrid.heights` 是字段误称，实际比较 `elevations_m`。
该咨询不是原生 Stop hook 的轮次验收。

读取链条为：geoid 校验与加载 → DEM 全文件哈希 → 完整目标坐标 →
CRS/源像元索引与边界检查 → 源包围窗口 → mask/scale/offset →
原源像元中心的 geoid 转换 → metadata/source_id → 不可变 TerrainGrid。
其中 TerrainGrid 会复制数组并构造不可变 bytes；只把 target 换成 memmap 不能消除该峰值。
哈希仍逐次完整验证，不能用路径/mtime 静默替代内容身份。

站点 108.9°E / 34.24°N，60 m 当地网格，现有 Copernicus DSM 与完整 EGM2008 网格；
文件身份、软件版本、源窗口和各阶段 RSS 端点见机器记录。
源存储为 int16、256×256 块；读取时转换为 float64。

24 km 的最大 traced allocation 约 97.64 MiB；它包含各阶段存活的 Python/NumPy
分配，不是该阶段的增量，也不覆盖所有 GDAL/PROJ 原生分配。不能与 RSS 相加。
3 km 的全过程峰值由加载前的进程历史峰值主导，不能解释为小窗口本身用了 154 MiB。
两次最终运行是独立进程但有时间重叠，系统页缓存未控制，含探针开销；本表不是吞吐量基准或 SLA。
写入没有 fsync，不能据此声称持久化磁盘带宽。

24 km 输出与 `output/m3-radius-24km-20261009/xian_city-ellipsoid.npy`
逐值一致（包括 NaN 位置），探针没有改变该场景数值。
第一版探针把 context manager 退出行重复标记为一个阶段；最终版每个标记仅执行一次，
两个最终记录均为 11 阶段。旧 output 保留，不作为最终测量依据。

## 方案比较与选择

| 方案 | 优点 | 代价/风险 | 决定 |
|---|---|---|---|
| 单纯提高现有限制 | 修改少 | 全量坐标、索引、geoid 临时数组和源窗口继续平方增长 | 拒绝 |
| 目标 tile + 局部源窗口 + 有限内存输出 | 延续当前 TerrainGrid 接口，易逐值比较；大临时数组局部化 | 重复源块读取、需要两遍规划；输出仍平方增长 | G02 首选 |
| 按射线查询/有界块缓存 | 少量方位时无需完整当地网格 | 改变剖面接口和查询生命周期，验证范围大 | 后续需要时再评估 |
| memmap/磁盘栅格后端 | 输出可超 RAM | 现有 TerrainGrid 会复制，需重新设计所有权/不可变性/文件寿命 | 本批不引入 |

G02 使用规划与执行两遍处理。第一遍分块转换目标坐标，汇总精确合法源像元的全局
包围窗口，复用原先五位置的 native spacing 检查；不能用少量角点估计替代真实边界。
规划阶段不读取高程大窗口。第二遍重算相同坐标，读每个 tile 的最小源窗口，
执行相同 floor、掩码、scale/offset 和源像元中心高程转换，填入有限输出数组。
tile 源窗口超预算时细分；最小 tile 仍不能处理则报明确错误。
这种两遍方案用额外坐标计算换取全局索引有界，保留当前小窗口拒绝条件。

## 本批冻结预算（工程选择，尚待 G02 实测通过）

测量显示旧 24 km 路径峰值约 206 MiB。为保留原始取值、允许两次外层扩展，
下一批在相同 60 m 分辨率验证 36 km 和 48 km；分别为 1203² / 1603² 目标格，
约 11.04 / 19.60 MiB 最终 float64 数据。按现有源窗口面积比例估计，
源包围面积约 6.64 / 11.80 百万格，超旧单窗口限制；这些是估计，需规划器给出实际窗口。

- 整进程峰值 RSS 验证预算：512 MiB；从当前实测预留超过一倍余量。这是本批测试环境的退出条件，不是任意平台的 RSS 硬保证。
- 目标总格数最多 4,000,000（约 30.52 MiB 最终数据），在任何网格数组分配前检查；不再让全量坐标数组随总格数增长。
- 初始 tile 128×128；每个源读取窗口最多 262,144 格，超限细分，不截断或降分辨率。
- GDAL cache 保持 32 MiB；原生块仍不得超 4,000,000 格，并纳入预测预算。源 dtype itemsize 也必须计入，而非假设都为 int16。
- 保守计划模型：环境/PROJ 预留 192 MiB + 三份输出数据 + 32 MiB GDAL cache + 原生块临时副本预留（至少按源 dtype 与 float64 各副本计算）+ 32 MiB tile 工作区。预计超过 512 MiB 则在执行前拒绝；估计通过仍须实测验证。
- 时间、总读量不设臆造业务限值，但必须记录读窗口数/总格数、重复读取、哈希、两遍坐标转换、geoid、写出耗时；资源退化显著时回到选型审查。

上述模型是需要验证的保守工程估计，不是内存安全证明。RSS 由独立子进程测量，
预算测试若超标则 G02 不通过；实际部署硬上限需另外的进程资源管控。
如 36/48 km 仍不稳定，输出未验证状态，由 G03 处理契约，不能无限提高限制或改阈值。
地形半径 ≤100 km 的既有限制不变；48 km 的局部几何/曲率误差仍属于 G05 待验收事项。

## G02 一致性与反例清单

1. 冻结旧读取器作为小窗口测试 oracle，记录源码哈希；新旧使用同一输入和同一声明。
   合成 WGS84/投影/旋转 affine、真实 3/6/24 km，使用至少两种 tile 大小。
2. `elevations_m` 逐值一致、NaN mask 完全一致、源像元索引一致；包含 geoid 的路径也先要求精确一致。
   若 PROJ 分块产生可证明舍入差异，必须先定位、记录影响并审查，不预先允许宽泛容差。
3. 原点、网格半像元定义、floor 与像元边界两侧、scale/offset、nodata、接收点 nodata、
   部分交叠/完全不相交、非有限坐标、未知 CRS、声明/hash 错配、重复 geoid、细于原生 spacing 的拒绝条件都须覆盖。
4. 多个 tile 跨原生存储块、极稀疏合法像元、超预算 tile 细分、最小 tile 仍超预算；
   检查每次实际 read 的窗口，不能只测最终 RSS 后假定所有中间读取有界。
5. 合成大包围窗口证明新路径不触发一次性巨窗；总目标超限须在分配前失败，
   原生块过大须拒绝。错误不得变成已知零损耗，不能偷偷降低分辨率或半径。
6. 数值 metadata/source_id 延续原物理语义；同场景改变 tile/cache 不改变身份。
   新的读取策略、访问窗口统计放入独立运行诊断，不能直接混入当前 `identity(metadata)`。
   DEM/geoid/声明/位置/分辨率/半径变化的身份测试继续保留。
7. 人工格与真实 3/6/24 km 等价通过后，才运行 36/48 km 资源检查；扩大范围后保存输入、源码、窗口、预算及失败记录。
   通过读取测试不代表数值模型验收或有限范围之外充分。
