## 1. 第一周是否完成

**第一周的最小开发目标已达到，可以开始第二周；验收结论应为“在明确范围内通过，保留数据、环境与工程收尾项”。目前不适合笼统标为所有问题已解决或可直接进行可信的真实地形实验。**

第一周预先定义的目标是：完成一个真实数据小样本的读取审计，完成一个人工几何下的单链路计算，保存可追溯的分量与运行记录。这些已有代码和实际运行证据。真实地形损耗计算、完整轨道、过境和选址并非本周承诺的实现范围。

需要修正此前简略表述的理解范围：

- “第一周开发完成”指最小工具流程已实现，不是 M0–M6 完成。
- “真实数据审计完成”指已读到数据并核查、报告其问题，不是数据已获物理可信认证。
- “通过复现”指当前环境、当前源码、同一配置的重复运行，不是已在另一干净环境复现。
- “120 passed”是测试结果；另有一个明确未修复的已知失败，没有全部物理测试通过的含义。

不提供总完成百分比：配置、来源、物理模型和任务评价的工作量与验证难度不相同，用文件数或测试数计算比例会误导。

## 3. 已解决的问题

### S01：缺少一个可独立运行的单链路实验入口

新增 `experiments/pilot.py`，支持 `run` 和 `validate-data`。解析计算不依赖 DEM、TLE、网络或 GUI，可以单独执行并输出完整记录。

**已解决范围：** 一个接收点、一个人工卫星相对位置、一个频率、一个标量预算。

**备注：** 真实样本审计与人工链路计算是两个用例。审计过 DEM，并不表示解析结果已经计算了这个 DEM 的传播影响。

### S02：新入口缺少单位、参数和功率口径约束

新增严格 pilot 配置，拒绝缺字段、未知字段、非法频率、零/负距离、NaN/Inf 和混用功率模式。支持 EIRP 或“发射功率＋发射增益”二选一；按声明的效应检查重复计损。负附加损耗允许表达明确的局部增强。

**已解决范围：** 新 pilot 配置与预算组合。

**备注：** 依赖输入正确声明所含效应，不能自动识别任意外部求解器隐含的天线或自由空间项；旧 legacy 入口没有因此自动获得相同保护。

### S03：未知损耗可能被当作零，导致过度乐观的结果

显式区分 `known`、`unknown`、`not_applicable`、`not_computed`、`failed`。不可用量用空值表达，未知分量会阻止得到正常接收功率。演示中的零损耗有明确的人工假设原因。

**备注：** 在本次 550 km 自由空间例子中，局部损耗为零是“关闭局部效应”，不是“已求解真实地形且无遮挡”。

### S04：缺少可审核的旧输出读取与标签转换

提供显式 label adapter，保留路径、哈希、shape、dtype、单位、包含效应和解释依据。实现 dBW→dBm 的 +30 转换，以及带完整公式和参数的仿射反归一化。未知标签和不兼容口径不能直接用于 dB 误差比较。

**实际处理：** 读取同一帧的 L1、L2、L3 与复合损耗，四个数组的输出哈希与历史 manifest 一致。

**备注：** 当前批次为 `net_loss/path_loss`，不是接收功率；原始归一化标签并未出现在这批真实样本中，反归一化能力由人工测试验证。

### S05：缺少保留缺失值的 DEM 检查通道

新增原生窗口审计，保存原始像元和独立 nodata 掩码，记录像元中心、仿射变换、坐标、分辨率、有效比例和边缘距离，不做中位数填充或重采样。

**备注：** 这是新增审计路径。旧 `geodata.read_dem()` 的填充行为没有修复，旧地形算法也没有更换。

### S06：实验结果与代码、输入、配置无法对应

新增运行目录记录，保存配置原文与规范化配置、输入哈希、源码逐文件指纹、提交号、dirty 状态、依赖、硬件、日志和输出校验清单。已有目录拒绝覆盖；正常可写条件下，捕获到的失败会留档。

**备注：** 指纹能识别代码是否变更，不能从哈希反推出未归档的源码。当前工作区中的未跟踪文件仍须保留，不能仅靠旧提交号恢复本次新实现。发布归档与 Git 提交是后续收尾。

### S07：缺少解析正确性和重复运行证据

增加局部几何、FSPL 独立公式、距离/频率倍增、功率平移、缺失状态、重复效应、单位转换、坏哈希、失败留档和 CLI 集成测试。实际保存两次结果，并逐字节比较确定性文件。

**备注：** 证明了被覆盖的输入与规则，不代表实现已不存在任何缺陷，也不覆盖全部 M1/M3 物理条件。

## 5. 测试结果及其含义

最近一次完整测试为 `120 passed, 1 xfailed in 4.13s`，基线为 `100 passed, 1 xfailed`。增加的是 20 个通过的 pytest 案例，包含参数化案例，不是新增 20 个独立功能模块。

本次复核确认：记录中列出的核心源码与 `pyproject.toml` 哈希仍与当前文件一致。此次为报告复核，没有重新运行整套测试、重新计算真实 DEM 哈希或改动求解逻辑。

| 已有证据 | 能支持的判断 | 不能支持的判断 |
| --- | --- | --- |
| 解析 FSPL 与功率变化测试 | 选定标量公式和输入行为正确 | 大气/地形/方向图模型已验证 |
| 未知分量与重复效应测试 | 新入口能拒绝这些明确定义的错误 | 任意外部模型口径都能自动识别 |
| 四数组重组最大差 0 dB | 存储层 L1+L2+L3 与复合数组一致 | L1/L2/L3 本身物理正确 |
| 源文件哈希一致 | 本次使用的字节与固定记录相同 | 来源记录本身真实、模型正确、历史环境完整 |
| 两次链路 JSON 一致 | 同环境同配置的解析结果确定 | 跨机器或不同库版本已一致 |
| CF-01 xfail | 缺陷被稳定复现和明确登记 | 缺陷已修复或地形测试已通过 |
| 三个解析 fixture | 有可复用的小场景定义和预期量 | M3 地形求解器、M5 事件检测器已通过验收 |

`xfail` 是“预期仍失败”，因此 pytest 不把它视为新的回归失败。它不是通过：500 m 海拔平地的正确性要求目前仍未满足。

## 6. 已实际得到的结果

### 6.1 人工链路

固定配置：14.5 GHz、550 km、方位 0°、仰角 45°、EIRP 55 dBm、接收增益 0 dBi。固定大气与局部零效应假设下：

- FSPL：170.48239703458438 dB。
- 接收功率：−115.48239703458438 dBm。
- 门限为空，裕量为 `not_computed`，服务资格为 `unknown`。
- 配置、输入及链路结果在两次独立命令行运行中逐字节一致。

结果与分量见 [link_records.json](link_records.json)。当前没有保存一条“已验证真实地形损耗的完整链路”。

### 6.2 真实样本

- 数据来自 `Satellite-Ground-Radiomap/benchmarks/golden_scenes`，四个 256×256 float32 数组及其配置与来源记录实际可访问。
- 上游记载 IONEX/ERA5 使用回退，卫星身份记录为空；已保存这些限制，没有以默认真值替代。
- L1 为含减去发射增益的净损耗；L2 存储值全零，原因未通过独立物理计算确认。
- DEM 读取了原生 64×64 窗口，间隔 `1/3600°`；当前窗口没有 nodata，但缺失值规则仍保存。原始值 395–426，垂直单位未确认。
- 最小轴向窗口边缘距离约 817 m。这个诊断量不是“周围 817 m 内外都已充分考虑地形”的认证。

### 6.3 性能

| 操作 | 观测结果 | 备注 |
| --- | --- | --- |
| 人工几何 | 中位数 2.44 μs/次 | 五组，每组 100 次 |
| FSPL | 中位数 5.05 μs/次 | 同上 |
| 完整链路记录计算 | 中位数 94.97 μs/次 | 包含组装记录，不含写盘 |
| DEM 全文件校验 | 最终运行约 6.56 s | 初次约 9.14 s；未控制 OS 页缓存 |
| 64×64 DEM 读取和审计 | 约 0.050 s | 单次观测 |
| 解析/审计峰值 RSS | 约 199.5/212.5 MiB | 含 Python 与地理依赖，不是纯算法内存 |

这些值只用于当前小样本预算。20–25 小时是原计划人力估计，本次没有独立记录实际有效开发工时，不能用计划值冒充实耗。

## 7. 当前可以使用和不应使用的能力

**可以使用：** 新 pilot 做人工几何与标量链路检查；读取声明了口径的旧 NPY；校验来源字节；检查 DEM 小窗口；保存运行证据；作为下一周修复和验证的基础。

**尚不能据此完成：** 可信真实地形覆盖图、DEM 高度到轨道几何的统一计算、完整单星过境、方向缓存加速、实际服务窗口、候选点最优部署或论文所需的精细传播收益结论。

旧 `sat-cover` 入口仍使用旧流程。本周新入口的防错能力不能当作旧入口已经修好的证明。

## 8. 下一步建议与关闭顺序

1. 将本报告中的状态作为验收口径，避免用“全勾选”替代问题清单。保留源码、样本清单和报告；如需形成可交付版本，再做提交/归档收尾。
2. 先解决 CF-01、DEM 垂直条件与 PROJ 环境这三项，保留解析链路作为稳定对照。
3. 再实现真实逐点几何和必要的 TLE 政策，逐步扩展 E1。不要直接扩大旧地形地图生成规模。
4. 在地形主计算有可信的小样本结果后更新整体工时、内存与方向查询预算，再推进 M2/M4/M5/M6。

CF-01 关闭必须以正确物理用例通过为依据；未知元数据关闭必须有来源证据；复现关闭必须有独立运行证据。修改状态字段或移除失败标记本身都不是问题解决。
